# 개요
본 앱 (학습 서버)을 활용하여 언어 모델 앱 (모델 서버)에 학습 내용 반영

# 활용 정보
- 학습에 활용하는 엔드포인트는 `root.rest.AgentCont` 내의 엔드 포인트
- 단어 목록 포맷: `n(번호)	lang	word	type	date	memo` (lang, date 는 학습과는 무관하므로 무시)
- 모델 서버 프롬프트 `GET` `localhost:8081/plm?pureSrc=프롬프트_내용&export=true`

# 업무 흐름
1. 담당자로부터 단어 목록을 전달 받음
2. 단어 단위로 순회하며 학습 과정 진행
3. 모든 단어 학습을 마친 경우 결과 보고
4. 담당자가 학습 과정을 검토 후 실반영/반려
5. 반려 시 반려 사유를 참고/개선하여 다시 진행 (모든 단어가 실반영 될 때까지)
6. 모든 단어 수행 완료 시 새로운 목록 전달받아 1부터 진행

# 학습 과정 (per 단어)
1. 해당 단어를 활용한 자유로운 주제의 요청 문장 정의 (3~23자)
2. 정의한 요청 문장으로 모델에 프롬프트했을 때 **응답이 자연스러운지 판단**하여 자연스럽다면 '학습 불필요'로 기록 후 다음 단어로 continue
   (자연스럽지 않거나, 응답이 없거나, 오류가 발생한 경우 3번으로 이어서 진행)
3. 1번에서 정의한 요청 문장의 응답으로 자연스러운 응답 문장 정의 (3~30자)
4. 정의한 요청, 응답 문장으로 에이전트 타스크 생성
5. 1번에서 정의한 요청 문장으로 `/understand` 호출하여 해당 문장을 올바르게 분해, 할당하는지 확인
   (올바르지 않다면 올바른 응답이 올 때까지 다음 기능들을 활용하여 교정 진행)
   (올바른 응답으로 교정하는 데 필요한 기능 호출 횟수 최소화)
   - 신규 단어 등록
   - 신규 컴파운드 등록
   - 신규 콘텍스트 등록
   - 단어 타입, 메모 변경
   - 콘텍스트 조정
6. `learnContext=false` 로 요청 문장 커밋 진행
   (커밋 실패한 경우 `learnContext=true` 로 커밋 진행)
7. 3번에서 정의한 응답 문장으로 `/understand` 호출하여 해당 문장을 올바르게 분해, 할당하는지 확인
   (올바르지 않다면 요청 문장과 동일하게 교정 진행)
8. `learnContext=false` 로 응답 문장 커밋 진행 (커밋 실패한 경우 `learnContext=true` 로 커밋 진행)
9. 요청, 응답 문장 Q-A 연결
10. 모델 서버 리로드 후 요청 문장으로 다시 프롬프트하여 자연스러운 응답이 오는지 여부 기록
   (**정의한 응답 문장이 오는지가 기준이 아님, 응답이 자연스러운지 여부**)

## 학습간 동음이의어 관련 가이드
현재 등록되어있는 단어 중 동음이의어 단어는 다음과 같은 경우들이 동시에 존재
- 각 동음이의어 단어가 별도로 등록
- 한 단어가 가능한 모든 동음이의어의 역할 병행

위 경우들 중 어느 경우인지는 메모를 보면 식별 가능

신규 동음이의어를 등록해야하는 경우: 현재 필요한 의미만을 갖는 별도 단어로 등록 바람
